# Cinematic asset manifest

Every asset used by the Engineering Observatory films, where it came from, its licence, and where it lives.
Production sources (Blender scripts, downloaded scans, raw renders) are kept apart from what the website serves.

| Location | Contents | Served to visitors |
| --- | --- | --- |
| `blender/scripts/` | Scene scripts (the films are generated from code; no .blend files are required) | No |
| `blender/assets/polyhaven/` | Downloaded CC0 scans + `LICENSES.json` ledger (URL, bytes, SHA-256, date) | No |
| `blender/renders/<variant>`, `blender/renders/<scene>-<variant>` | Raw PNG renders + `frames.jsonl` version log | No |
| `public/cinematic/<scene>/<variant>/` | Encoded WebP frames, `poster.webp`, `manifest.json`, `packet.json` | Yes |

## 3. Procedural content (written for this project)

All geometry in the three films is generated by the scripts: the display stack and driver board, the atrium,
galleries and Git walkways, the CI hall and its stations, the data hall racks and services, the runtime server
interior, the SQL Server vault and index, the library, its furniture and the stylised reader. Server LEDs, data
pulses and record rows are procedural shaders driven by a frame clock. No third-party models are used.

The reader in the library film is an anonymous, stylised figure (metaballs), seen from behind and labelled on the
page as a conceptual illustration. It does not depict a real person.

## 5. Fonts rendered into frames

Consolas and Segoe UI Bold (Windows system fonts) are used by Blender to rasterise labels into the frames. The
fonts themselves are not distributed with the site.

## 6. Version guard

Each Blender script appends `{frame, generator, variant}` to `frames.jsonl` after writing a frame, and
`Scripts/encode-cinematic.cjs` refuses to encode a frame whose last log entry does not match the generator recorded
in `packet.json`. Frames of an older film therefore cannot be mixed into a newer sequence. The v4 pipeline frames
rendered before logging existed (jobs 075–078-1) were back-filled from their modification times, which are all
later than the start of the v4 production series (2026-11-19 11:10:30 UTC) with the v4 script unchanged since
11:08 UTC.
